# Discord integration — what was added

## New DB tables (server/models.py)
- **Team / TeamMembership** — drivers can belong to teams. A team has a
  permanent `invite_code` used both by drivers joining on the web and by
  a Discord channel subscribing to that team's announcements.
- **DiscordChannel** — maps a Discord channel to either a team
  (`team_id` set → gets that team's TEAM_BEST posts) or globally
  (`team_id` null → gets WR posts). Registered via `/link_team` /
  `/link_global` in Discord.
- **LinkCode** — one-time, 10-minute codes generated by the web app
  (`POST /accounts/discord/link-code`; the old `/teams/discord-link-code` is a deprecated alias) and redeemed with `/link <code>` in
  Discord, connecting a Discord user to a Driver row.
- **RecordEvent** — the announcement outbox. Written by
  `server/records.py` right after a lap upload commits; polled and
  cleared by the bot every 10s.
- **Driver.discord_user_id** — new column, set once `/link` succeeds.

## Record detection (server/records.py)
After `telemetry.py`'s `upload_lap` commits a genuinely new lap, it calls
`evaluate_and_record(db, lap)`, which checks (valid laps only):
- **PR** — driver's own best on this track/car
- **WR** — best by anyone on this track/car
- **TEAM_BEST** — best among any team the driver belongs to, on this track/car

Each one that's newly broken gets a `RecordEvent` row. PR isn't broadcast
(only queryable via `/pb`) since it's not team/server-wide news.

## Web endpoints (server/routers/teams.py)
- `POST /teams` — create a team (name), creator auto-joins
- `POST /teams/join` — join via invite code
- `GET /teams/mine` — list your teams + invite codes
- `GET /accounts/discord` — is this driver linked (a flag only; the Discord id is never sent to the browser)
- `POST /accounts/discord/link-code` — get a one-time code (`ABCD-EFGH`, 10 min) for `/link` in Discord; 409 if already linked; invalidates earlier unused codes
- `DELETE /accounts/discord` — unlink (idempotent) and cancel any pending code
- `POST /teams/discord-link-code` — deprecated alias of the link-code endpoint above

Wire it up: `main.py` now includes this router alongside the existing ones.

## The bot (discord_bot/bot.py)
Runs as its own process, talking directly to the same database as the
FastAPI server (same deployment, simplest option — swap for HTTP calls to
the backend if you ever split them apart).

Slash commands:
- `/link <code>` — connect your Discord account to your driver profile (single-use, case/space/dash-insensitive, throttled after repeated wrong guesses; reply is visible only to you)
- `/unlink` — disconnect your Discord account from your driver profile
- `/link_team <invite_code>` — this channel gets that team's best-lap posts
- `/link_global` — this channel gets world-record posts
- `/pb <track> <car>` — your personal best
- `/wr <track> <car>` — current world record
- `/teambest <track> <car> [team]` — your team's(s') best
- `/leaderboard <track> <car> [limit]` — top laps, one per driver

Background loop: every 10s, posts any un-announced `RecordEvent` rows as
embeds to the right channels, then marks them announced.

### Running it
```
pip install -r discord_bot/requirements.txt
export DISCORD_BOT_TOKEN=your-bot-token
python -m discord_bot.bot
```
Needs `LMU_GARAGE_DB_URL` set the same as the server if you're not using
the sqlite default, so both processes see the same data.

## Naming note
Kept the bot in `discord_bot/`, not `discord/` — a top-level `discord/`
folder shadows the `discord.py` library's own import (`import discord`)
when Python resolves modules relative to the working directory.

## Still open (same spirit as the existing "dev-only" notes in this repo)
- Bot ↔ server share a DB directly; fine for one deployment, not for
  scaling the bot separately.
- No web UI screens for team create/join yet — only the API endpoints.
- `/link_team` and `/link_global` have no permission check — anyone who
  can run slash commands in a channel can register it. Worth gating on
  "manage channels" Discord permission before this goes further than
  internal testing.


## V0.8.7 — account linking rework

All linking rules live in `server/discord_link.py`, shared by the web API
and the bot, and are covered by `tests/test_discord_link.py` (real
database, including the bot commands driven through their real callbacks).
Fixed: there was no way to unlink (the bot said "unlink first"), the web UI
showed no status, an already-linked driver could be silently overwritten,
several codes could be live at once, and codes were 6 characters from an
alphabet with lookalikes and `-`/`_`. Codes are now 8 characters from an
unambiguous alphabet, shown as `ABCD-EFGH`; older 6-character codes still
redeem.
